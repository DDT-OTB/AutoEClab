# 实验方案文件管理

在左侧“实验方案”或编排区域的“管理方案”打开文件管理页面。切换页面会保留当前编排草稿。

## 浏览与筛选

支持按文件名、方案 ID 或描述搜索，按泵阀流程、包含测量、空白草稿和待检查筛选，以及按修改时间、文件名或步骤数量排序。

选择一行会显示文件大小、修改时间、步骤数和同名说明文档是否存在；JSON 页签查看原始内容，也可以下载。双击有效方案，或点击“进入编排编辑”，会将文件加载到原有的流程编辑器。

格式不正确的 JSON 仍会出现在列表中，便于查看、下载和处理。非版本 2 的文件不能直接进入编排、复制或重命名。

## 新建、导入与编辑

新建与导入都会进入编排编辑器，首次成功保存后才创建文件。支持从本机选择 JSON，也支持粘贴内容。文件名和配置 JSON 使用英文。

编辑已有方案时，保存需要匹配加载时的文件版本。编辑器中修改方案 ID 后保存会另存为新文件；如果需要移动原文件名，使用文件管理中的“重命名”。

## 复制、重命名与删除

- 复制会创建独立的新文件，更新内部方案 ID，并生成对应说明文档；原方案保持不变。
- 重命名同时移动 JSON 和同名 Markdown，更新方案 ID 与生成的摘要，保留已有手写说明。
- 删除需要再次确认，并同时处理 JSON 与同名说明文档。删除已加载的文件时，编排内容会保留为未保存草稿。

这些写入操作仅对管理员开放，观测员可以浏览、下载和预演。后端会再次检查角色、CSRF 和目标文件名。

## 版本与备份

重命名、复制和删除都提交所查看的 JSON 内容版本。若其他人已经修改文件，后端返回版本冲突；界面刷新列表，使用者检查最新内容后再操作。

覆盖、重命名、复制和删除前，源文件与说明文档会备份到本机 `data/backups/<operation-id>/`，并记录英文 `operation.meta.json`。备份目录被 Git 忽略，恢复由服务器管理员进行，网页暂不提供恢复按钮。

单次文件写入失败时会尝试恢复原文件组合，备份会继续保留。运行中的控制程序正在使用的方案不能覆盖、重命名或删除。文件管理操作不会读取串口或执行硬件动作。

## API

所有接口均要求登录，写入还要求管理员角色和 CSRF 校验。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | /api/experiments | 文件目录及元数据 |
| GET | /api/experiments/{id} | 读取可解析方案与版本 |
| GET | /api/experiments/{id}/content | 原始 JSON 文本、文件状态和版本 |
| POST | /api/experiments | 保存或创建方案 |
| POST | /api/experiments/{id}/rename | new_id、expected_version |
| POST | /api/experiments/{id}/duplicate | new_id、expected_version |
| DELETE | /api/experiments/{id} | expected_version |

实际方案、备份、账号和部署配置不进入 Git 仓库，测试仅使用合成文件。
