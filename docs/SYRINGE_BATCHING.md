# 注射泵按总量分次注入

在网页动作参数中填写“注入总体积”。注射器物理容量保持 25 mL，服务器默认限制每次最多 20 mL；总体积超过单次上限时，在同一个实验动作内顺序执行多个吸液、注入循环。

| 总量 | 分次计划 |
| --- | --- |
| 20 mL | 20 mL |
| 25 mL | 20 + 5 mL |
| 30 mL | 20 + 10 mL |
| 40 mL | 20 + 20 mL |

上限由 `config/syringe_policy.json` 配置。`max_stroke_volume_ml` 为每次注入上限，`max_strokes_per_action` 限制单个动作的最大分次数。有效上限同时受注射器物理容量和可表示的整数步数约束；硬件容量参数不需要改成 30 或 40 mL。

方案 JSON 仍只填写总量，不接受客户端自定义的底层行程或串口命令：

```json
{
  "device": "syringe_c",
  "operation": "inject",
  "fluid": "electrolyte",
  "volume_ml": 30
}
```

正式实验应在此前明确选择注射泵入口来源，水为 5、电解液为 6，并完成固定的前置准备。前置回零仍先切水并回读；主体动作开始后按所选液体执行，不在各分次之间自动回零。

每次吸液前回读入口通道，随后由已有 SY11 驱动执行吸液、内置阀切出、注入并返回本次初始位置；完成位置和就绪回读后才进入下一次。序列、原始总量、分次计划及服务器规则一起冻结；规则变化后需要重新准备。单个 30 mL 动作仍按一个动作显示，详情显示第几次、当次体积和已完成分次的标称累计量。

所有液体的电解池预算仍合计不超过 40 mL，分次边界不会重置液量。例如先注入 15 mL 水，再注射 30 mL 会被拒绝。活塞步数换算值不代表流量传感器实测，量化后的预计注入量也计入容量检查。

错误、入口不匹配或停止会终止后续分次，不自动重试已完成的部分。日志保留已完成分次及其标称累计量；中断分次的实际排液可能不确定，需要现场检查，不能直接重按整个总量作为续传。正式实验重新运行仍须重新完成排空与人工确认。
