# 必需的前置准备功能块

每个正式实验必须且只能以前置准备块开始。`mode: "debug"` 调试方案不强制此块，支持完整的多功能块编排，详见 [调试编排](FUNCTION_BLOCKS.md#调试编排)。调试中主动加入此块时仍须完整执行，且只能放在首位。新建方案自动加入；旧方案载入编辑器时会补齐，保存前原文件保持原样。界面将其固定在首位，不提供删除、复制或移动按钮。后端独立验证类型、步骤和顺序，不依靠块名称判断。

```json
{
  "type": "preflight",
  "id": "experiment_preparation",
  "description": "Mandatory experiment preparation",
  "steps": [
    {"device": "valve", "operation": "select_syringe_water_if_used", "route": "water"},
    {"device": "syringe_c", "operation": "home_if_used"},
    {"device": "cell", "operation": "drain_to_waste", "route": "waste"},
    {"device": "cell", "operation": "confirm_empty"}
  ]
}
```

将这块放在版本 3 实验的 `blocks[0]`。旧版 API 的版本 2 格式可将同一个块放在顶层 `preflight` 字段。单块导出文件还会包含 `schema_version: 1`、`kind: "function_block"`。完整例子见 `config/examples/demo_blocks.json`，默认块定义为 `config/preflight_block.json`。

## 四个固定步骤

1. **按需切水并回读**：正式实验含 `syringe_c` 时，先把入口阀切到水（固定通道 5），回读阀就绪状态和实际通道。未到位、串口无应答、配置中没有明确的 water=5 或回读发生变化时，禁止发送回零命令。没有使用注射泵时跳过切水和回零。
2. **回零**：水路确认后，执行机械回零与设备身份、零位、阀位、缓冲和就绪核验。选水和回零在同一设备锁下按固定顺序执行；回零前再次读取水路，前端不能改为电解液。切水保证入口来源，不代表注射器内原有液体已经被水替换，仍须确认残液排出和接液条件。
3. **排空**：当前构型使用 `route: "waste"`，排液泵直接排入一个废液瓶，不操作注射泵入口阀；调用已有排液控制，体积由服务器安全策略指定，当前为标称 40 mL。不能在块中调小这项体积，也不能在运行请求中替换流路。
4. **人工确认空池**：排液成功后暂停。管理员现场检查并勾选确认，再继续正式实验。静态 JSON 的 `confirm_empty` 是交互步骤，不是已确认结果；不接受 `confirmed: true` 等预置确认字段。

## 运行界面

运行页不再单独显示“本次未校验”或排空准备状态条。点击“运行已载入流程”后，流程执行窗口内按前置功能块展示进度。管理员确认接液安全后点击“开始前置功能块”，回零与排空顺序推进；到人工确认步骤时暂停，再点击“确认空池并继续流程”。

排空失败、回零失败或停止均不会继续正式实验，也不会自动重试。当前没有液位传感器，计时排液只证明动作已完成，不能自动代表电解池已空。

## 执行与恢复

- 预演、保存、准备、正式启动和执行器入口均检查前置块；缺少、重复、放错位置、修改固定操作或伪造确认字段的方案不能放行。
- `POST /api/execution/advance` 每次只推进一个已授权阶段。请求要求管理员会话、CSRF、固定运行 ID 和准备版本。初次请求须现场确认回零及接液条件，后续空池确认必须单独发生在排液完成后。
- GET 查询只读取进度，不发起设备动作。网页只在本次已授权、状态连接有效且流程未改变时推进自动阶段；人工确认永远不会自动提交。
- 关闭网页或断开连接时，已经开始的设备步骤继续由原控制器完成和清理，之后不会自行跨过人工确认。重新登录后可点击“恢复未完成流程”；恢复本身不启动动作，需显式继续。
- 重复提交同一阶段不会重复回零、排液或启动正式实验。每次确认和校验仍绑定本次不可变方案，过期、其他控制操作或参数变化会使证明失效。
- 所有液体的 40 mL 池内容量预算继续按正式动作逐步校验；前置排空不重复计入正式动作列表。正式动作沿用原有泵阀控制与清理逻辑。

回零仍发送完整 `ZR`，不使用裸 `R` 恢复或软件置零。真实初始化记录、运行授权和确认结果保存在服务器私有数据目录，不写回方案 JSON，也不纳入 Git。

0.15.2 起使用四步模板。编辑器载入已知的旧三步模板时补入切水步骤，并保留其余实验动作；保存后使用新版。服务器部署会备份并升级已有方案和模板库中的已知旧前置块。不符合旧固定格式的自定义内容不会被猜测修正。旧准备快照和没有水路回读证明的回零结果不能用于新实验，需要重新准备。
